# EduMentor

Личное приложение для персонального обучения с ИИ. Только для тебя, без Google Play.

Стек: **Expo (React Native) + TypeScript + expo-sqlite + Zustand + OpenRouter (DeepSeek)**.

## Что уже готово (MVP-срез)

- 5 предметов, полное дерево тем для Математики (остальные — базовый набор)
- Профиль: XP, уровни, streak
- Чат с ИИ-преподавателем по каждой теме, с кнопкой «Я нихуя не понял»
- Режим практики: генерация заданий через structured JSON output, проверка ответов
- «Босс темы»: финальный экзамен на 20 заданий, открывает следующие темы
- Система ошибок: журнал mistakes + аналитика повторяющихся паттернов за неделю
- Spaced repetition (упрощённый SM-2) — считает даты следующего повторения
- Экран статистики ошибок по предметам
- Настройки: ввод своего OpenRouter API-ключа (хранится в SecureStore)

## Чего пока нет (следующие итерации)

- Диагностический тест при первом входе в предмет
- Режим "Мне скучно" — заглушка-кнопка ведёт в предметы, генерация мини-заданий не реализована
- Достижения (таблица `achievements` в схеме есть, UI и логика начисления — нет)
- Ежедневные задания (таблица `daily_tasks` есть, генерация плана — нет)
- Визуальная карта знаний как граф (сейчас список тем сверху вниз)
- Режим подготовки к контрольной
- Полноценные тесты/экзамены отдельно от "босса" (диагностика, checkup)

## Установка (на своём компьютере, с интернетом)

```bash
git clone <твой репозиторий>
cd edumentor
npm install
npx expo start
```

Дальше — отсканировать QR в Expo Go (для быстрой проверки UI) **или** собрать полноценный dev-билд, потому что `expo-sqlite` и `expo-secure-store` — нативные модули, и полная функциональность (БД, сохранение ключа) в чистом Expo Go может быть ограничена в зависимости от версии. Рекомендуется сразу собирать dev-client:

```bash
npx expo prebuild --platform android
npx expo run:android
```

Это требует установленного Android SDK локально. Если его нет — используй EAS Build (см. ниже), тогда сборка идёт в облаке и локальный Android SDK не нужен.

## Сборка APK через EAS (облако, не нужен Android SDK локально)

1. Зарегистрируйся на [expo.dev](https://expo.dev), создай проект.
2. Установи EAS CLI: `npm install -g eas-cli`
3. Авторизуйся: `eas login`
4. Привяжи проект: `eas init` (обновит `projectId` в `app.json`)
5. Собери APK: `eas build --platform android --profile preview`
6. Ссылка на готовый APK появится в терминале и на expo.dev — скачай и установи на телефон вручную (потребуется разрешить установку из неизвестных источников, т.к. приложение не из Google Play).

## Сборка через GitHub Actions (автоматически при пуше)

Workflow уже настроен в `.github/workflows/build-android.yml`. Нужно один раз:

1. Создать токен доступа Expo: на expo.dev → Account settings → Access tokens → Create.
2. В настройках GitHub-репозитория: Settings → Secrets and variables → Actions → New repository secret.
   - Имя: `EXPO_TOKEN`
   - Значение: токен из шага 1.
3. Запушить в ветку `main` — сборка запустится автоматически (или запусти вручную через вкладку Actions → Build Android APK → Run workflow).
4. Готовый APK появится не в GitHub, а на expo.dev в разделе Builds твоего проекта — workflow только запускает сборку в облаке EAS, не хранит артефакт в самом GitHub.

## OpenRouter API-ключ

1. Зарегистрируйся на [openrouter.ai](https://openrouter.ai), создай ключ (Keys → Create Key).
2. Пополни баланс (DeepSeek — один из самых дешёвых вариантов, конкретные текущие цены смотри на странице модели на openrouter.ai — они могут измениться).
3. Открой приложение → вкладка Настройки → вставь ключ.

Ключ хранится локально на устройстве через `expo-secure-store`, никуда кроме `openrouter.ai` не отправляется.

## Модель

По умолчанию используется `deepseek/deepseek-v4-flash-latest` (см. `lib/ai/openrouter.ts`, константа `DEFAULT_MODEL`) — актуальная модель DeepSeek на август 2026: дешёвая, быстрая, 1M токенов контекста. `-latest` в id всегда указывает на новейшую ревизию V4 Flash без ручных обновлений кода. Список актуальных моделей и их id всегда можно свериться на [openrouter.ai/deepseek](https://openrouter.ai/deepseek).

## Структура проекта

```
app/                    — экраны (expo-router, файловая маршрутизация)
  (tabs)/                — нижние табы: главная, предметы, статистика, настройки
  subject/[id].tsx        — карта знаний предмета
  topic/[id]/chat.tsx     — чат с преподавателем
  topic/[id]/practice.tsx — режим практики
  topic/[id]/boss.tsx     — босс темы (финальный экзамен)
lib/
  db/                    — SQLite: схема, seed-данные, репозитории (profile/subjects/mistakes)
  ai/                    — промпты, клиент OpenRouter, генерация практики, чат
  srs/                   — spaced repetition (SM-2)
stores/                  — Zustand: профиль, предметы
components/              — переиспользуемые UI-компоненты (Card, ProgressBar, тема)
```

## Важно: почему React Native, а не HTML/Capacitor

Изначальный опыт с Codex Mobile (single-file HTML + Capacitor) показал системные проблемы:
нестабильное сохранение файлов в APK, хрупкий нативный патч для Capacitor plugin registration,
сложность поддержки одного огромного HTML-файла при росте функциональности.

Для приложения, которым предстоит пользоваться каждый день для учёбы, эти риски неприемлемы.
Expo даёт нормальный SQLite без нативных патчей руками, компонентную структуру кода и
облачную сборку APK через EAS — то есть тот же принцип "пуш → готовый APK", что и раньше,
но без специфичных для Capacitor поломок.
